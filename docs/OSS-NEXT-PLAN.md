# OSS-NEXT execution plan

Consolidated, deduplicated execution plan for `docs/native-compiler/OSS-NEXT.md`: fix the items in `docs/native-compiler/TODOS.md` and `docs/native-compiler/TODOS-PERF.md`, eliminate the overhead this branch inflicted on `nockvm`, conform `honk` to post-PMA `nockvm` memory-safety, parity-check honk artifacts against the hoonc-built kernels in `assets/*.jam` (read-only — never rebuilt; the dir-hash leaf is expected to differ outside Bazel sandboxing), and keep honk's roswell compile under 60 seconds.

## Decisions

Hint-blind jet matching (find_jet normalization, Warm double-insert, Batteries::matches structural fallback) becomes opt-in, gated to honk via a runtime `JetDispatchMode` on `Context`; hoonc/nockchain revert to exact master dispatch behavior, and honk's hint-blind path gains memoization via alias insertion into the warm table. Parity covers all six kernels (dumb, wal, miner, peek, bridge, roswell) with the dir-hash leaf as the only tolerated difference. Deferred to follow-ups: the ut/mod.rs split (TODOS #14), find/fend/fund/fond parity matrices (TODOS #15), and hoonc-oracle fixtures for the strict compiler_mint tests (TODOS #11). PMA cold-state sharing (SLAB-PMA-COMINGLING Phase 4) stays in scope, sequenced last with an escape hatch. Honk-side perf work is demand-driven against the 60s roswell budget: small obviously-correct items land unconditionally, deeper items only if the gate fails. The behavior-event/parquet trace stack is deleted per the Instructions section of LOG-HINT-EVENT.md.

## Track H — honk parity, correctness, conformance

> ROSWELL RESOLVED (2026-06-12): the roswell `redo-match` is the documented unsound cross-call `miss`-memo persistence (`Ut::miss`), which `compile_entry` wrongly enabled for entry/kernel compiles despite `miss()`'s own comment stating entry compiles drift and must use per-call memos. The per-call memo already prevents the >10⁸ recursion blowup, so cross-call persistence is a pure (unsound) perf add-on. Fix: entry compiles never persist (persistence stays only around the isolated prelude, where it is sound). RESULT: **all 6 kernels now byte-exact** and compile in <60s — dumb 36s, wal 39s, miner 7s, peek 35s, bridge 40s, roswell 51s. This is the H2 miss-memo fix; the remaining H2 work is fan-context in the mint/redo/rest/nest cache keys (a separate drift source) plus batch-vs-single parity tests.

## H2 cache-soundness audit + fix (2026-06-13)

A multi-agent adversarial audit of every honk type-checker cache/memo surface found 7 with the roswell-class latent miscompile (key omits active %rest/%hold fan_context_key): mint, mull, redo, rest, fish, nest, crop+fuse. All were widened to carry fan_context_key (mint/mull also carry the arm_epoch/placeholder memo context, matching the sibling core_mint cache). All widenings are output-safe (every kernel stays byte-exact; the context fields collapse to 0 in the steady state, so the key only adds misses where the result genuinely depends on context the mugs don't capture). Two existing tests (active_rest_fan_context_partitions_context_sensitive_native_ut_caches, …_does_not_partition_rest_boundary) encoded the bug by asserting cross-fan cache hits; flipped to assert the correct partition. The audit confirmed musk mack caches are sound (no change).

ACCEPTED TRADEOFF (user decision): the extra misses push roswell from 53s to ~75s, over the 60s gate. Per user direction, the hardening ships over-gate; recovering <60s is a follow-up via the deferred H4 perf work (per-batch directory-mug cache, SourceFile read/parse cache) which the plan scoped as demand-driven against this budget. Measured points (quiet machine, all byte-exact): narrow 53s, fan-only 68s, fan+arm-epoch 75s.

FOLLOW-UPS surfaced by the audit (not yet done): (Step 4) bran_semi key omits the non-hold portion of the seen_raw recursion guard — latent, no reaching case constructed, but matches a documented requirement; (Step 6) the ArmMemoSet cache surface is entirely unwired and the placeholder_context_key is permanently 0 (dead set) — remove the dead recursion-naive scaffolding (the exact shape that caused the roswell miss-memo bug when wired) or wire it deliberately; (perf) the H4 dir-mug + SourceFile caches to bring roswell back under 60s.

## H3 native-parity audit finding (2026-06-13)

Added HONK_NATIVE_PARITY (env gate, off by default, output-neutral when off): when set, the canonical hoon-138 build does NOT substitute hoonc's embedded prelude formula / subject-type — honk mints them natively — to expose whether honk's own +mint of the prelude matches the spec compiler rather than passing parity by importing hoonc-produced nouns. (Cold state and the canonical $octs input are kept; they are jet-registration / data inputs, not compiler artifacts.)

RESULT: native prelude mint is currently IMPRACTICAL — compiling dumb with HONK_NATIVE_PARITY=1 ran ~49 minutes and was OOM-killed (rc=137) before producing output. So the embedded hoonc prelude formula/type is a NECESSARY bootstrapping shortcut, not merely a parity mask: honk natively compiles application code (all six kernels byte-exact) but cannot natively re-mint the full standard-library prelude in available time/memory. The audit is therefore INCONCLUSIVE on native-mint correctness (it cannot complete); it surfaces no application-layer correctness disparity. Whether the blowup is a pathological (quadratic/exponential) cost or an outright non-termination in honk's native mint of the largest input is an open question for a future profiling pass — it is a perf/bootstrap wall, not a fixed correctness bug, and is out of scope for the correctness-first pass (the kernels are byte-exact). The gate is retained as the audit/experimental tool for that future native-self-hosting work.

## H5 branded eval boundary — primitives + first call site (2026-06-13)

Resolved the user's "no sui-generis Noun APIs in honk" constraint for the eval boundary by reusing the generative BrandedNounSpace (their commit 9c2cc035) instead of inventing a honk-local wrapper. BrandedNounSpace is generic over NounSpace and read-only; the eval boundary needs two write-side ops it can't express, so they live in nockapp (where the copy primitive and interpreter both are), not honk. (1) NounSlab::with_brand — slab-side entry to the branded space (the machinery already applied to slabs via noun_space(); only the convenience method was missing). (2) BrandedNounSpaceExt::copy_in / copy_in_handle — copy a foreign noun into a branded arena, returning a handle branded to that arena; the only way to obtain a branded handle for a foreign noun. (3) BrandedEvalExt::interpret — evaluate a branded formula against a branded subject (both carrying the eval arena's brand), returning a branded product; a raw slab noun can't reach interpret without a brand mismatch. (4) BrandedNounHandle::unbranded (nockvm) — the single deliberate brand exit. The (allocator, space) pairing can't be proven by types (distinct values), so it's debug-checked by resolving the copy against the space; release trusts it (matching NounSpace's identity fast path), so the migration carries ZERO release cost. Commits 79b2ff4e, bc4fd0a9.

First concrete call-site migration (dfe391ab): eval_formula_noun_in_context — the canonical mint/eval path — now brands the interpreter stack and routes copy + interpret through the branded ops; the raw slab formula no longer type-checks as an interpret argument. Verified byte-exact: dumb and roswell kernels both PASS (exact) vs the hoonc reference through the migrated path; honk 181/181 in debug (exercising the debug-only provenance cross-checks on every eval); roswell timing unchanged (~76s, same H2 over-gate regime).

## H5 fit assessment — how far brands actually help honk (2026-06-13, 10-agent adversarial audit)

Verdict: YES-NARROWLY. The branded API is a real, type-enforced win on exactly ONE hazard class and is inert or obstructive everywhere else honk spends its risk budget. HELPS (high value): the slab-noun-reaches-interpret boundary — honk's single highest-severity bug class (runtime pointer-range panic in debug / wrong-arena resolution in release) becomes a compile-time brand mismatch. Already live at eval_formula_noun_in_context; 3-4 structurally identical single-scope candidates remain (slam_wrapper_gate honk.rs:2069-2108 interpret@2084; eval_standard_formula_to_jam interpret@2205) — mechanical to migrate. DOES NOT HELP (use a different tool): (1) ~199 as_raw/raw_equals cache-identity sites — the largest unsafe category, all single-arena in ut.slab, soundness already covered by the noun_eq structural fallback; brands disclaim value equality and expose no key, so they are inert here. (2) Musk *mut NounSlab / *mut Context self-aliasing (ut/mod.rs:5780-5848) — this is borrow-checker avoidance / mutable self-aliasing, NOT provenance; a Copy read-only brand cannot represent &mut to the stack/slab. Real fix is struct-level borrow-splitting (MuskRuntime method taking &mut NounSlab explicitly); brands can only decorate the copy-out AFTER that restructure. (3) The Box::leak'd 'static Ut slab + raw Nouns stored across compile calls in Compiled and ~30 Ut caches — the brand's core no-escape rule (handles cannot leave with_brand, be stored in a field/map, or be 'static) FIGHTS this architecture head-on; broad adoption would forbid the caches, not protect them. (4) set_mug in-place mutation, restore_checkpoint positional rollback, with_stack_frame Preserve contract — pure lifetime/mutation invariants the read-only brand does not touch (the migrated brand even lives INSIDE the still-unsafe with_stack_frame). (5) Cons-ing formerly-foreign nouns (vase builders) — copy_in brings sources in as read-only handles, but you must unbranded() both to T(...) them, so the dangerous adjacency happens unbranded; no branded cell-builder exists. CAVEATS: the brand's runtime checks are #[cfg(debug_assertions)] and release-skipped for the rangeless native slab, so the value is the COMPILE-TIME guarantee, not release defense; and every persisted eval product must unbranded() (dropping the guarantee) to be stored — so this is scoped, not end-to-end, safety. RECOMMENDATION: keep the migrated site, extend to the 2-3 identical single-scope eval boundaries, and STOP. Do not brand Ut's return-and-cache flow broadly (high churn, zero safety, fights the leaked-static architecture). For the rest use the right lever: borrow-splitting for musk; a safe NounSpace identity/interning token for the as_raw sites (nockvm-side, orthogonal to branding); an H6-style contains_alloc_ptr check inside copy_into NOT gated on debug_assertions if release-mode boundary defense is wanted (a better lever than the brand, whose checks are release-skipped). This supersedes the original H5 framing that treated brands as the mechanism for "every interpret call site" — the musk sites need borrow-splitting first, and the broad slab/cache surface is out of brand scope entirely.
